# Share buyback project: standing rules

- **No automated collection.** ASX, London Stock Exchange, FCA and NZX terms restrict it. The app and `fetch_from_list.py` read filings only from the location the user enters, `data\\allowed_hosts.txt` and internal addresses, through `sbb\\fetching.py`. Exchange sites are always refused; keep it that way. Figures and links are kept, not the filings. Do not add scraping, or bypass a site's bot checks, without the user confirming consent or a licence.
- **Never guess a figure.** Unclear values go to the review list. Every figure read from a notice keeps its page and source text, and its filing keeps its link. Filings are not saved; `filing_links.csv` lists every accepted link.
- **Never present a calculated figure as reported.** Mark new figures Reported or Calculated, and keep the working with them.
- **Never add or convert across currencies.**
- **One UI, per-country settings.** Market details live in `data\countries.json` and `data\constituents_<code>.csv`; a new country must not need a UI change.
- **Keep the documents current.** When a change affects setup, tabs, rules or limits, update `README_app.md` (Why / What / How / What if) in the same piece of work. Update `Research_Report.md` for rules and scope, and `Vendor_Study.md` for vendors.
- **Layouts are data.** A new exchange form is a definition in `data\forms\`, read by `sbb\forms.py`. Only an approved definition is used, and it keeps a sample in `tests\fixtures\`. SGX's sites are refused like the other exchanges'.
- **No AI tool and no key in the app.** The Layouts drafting tool and its AI connection were removed in v21. Do not add a model call, or any place to enter a Base URL, token or API key, without the user asking for it.
- **The Tracker derives, it never collects.** `sbb\tracker.py` works only from the readings already in `buyback.db`, writes only the `tracker_*` tables, fetches nothing and keeps no filing text. It shows one exchange at a time. A cross-check difference is listed, never applied.
- **Every filing is checked** by `sbb\validate.py`, whichever reader read it. A failed check never changes a figure; it sends the filing to review as CHECK_FAILED.
- **Hong Kong is read by `sbb\hkex.py`**, because its returns have rows that repeat. Never add a Hong Kong amount to another currency; a blank cancelled or treasury count is Not stated and goes to review, never assumed. A purchase also reported in another market is marked, not dropped (`data\cross_listings.csv`).
- **A Hong Kong mandate with no date is still a mandate** (`mandate_undated`): counted, never left waiting. A figure added from several rows is Calculated (`value_origin` "sum"). A balance (shares awaiting cancellation) is never added across filings.
- **Periods are derived, not stored** (`sbb\periods.py`): each filing's stated terms, set out from `documents.parsed_json`. It only reads. The programme row keeps the newest terms.
- **Read-only mode never writes to the published file**: it works on a private copy, hides and refuses every change. `maintain.py` publishes, lists or trims backups and compacts only when the user runs it, and deletes nothing without YES.
- **A start rebuilds only when something changed** (`ingest.state_signature`). Anything new that the figures depend on must be added to that signature.
- **The layout tool is separate** (`SHAREBUYBACK_layout_tool`). It drafts rules for a person to approve; the app stays free of AI and of any connection details.
- **Entries made by hand** (`sbb\hand.py`) are kept in `hand_entries` with their source, every change in `hand_log`, and each one as a reading (`documents.form` "manual") so rebuilds treat it like a filing read. Source is required; a delete needs a reason and keeps the entry in the history. Never work a figure out for the user (an end date stated as a period is typed by them; a size in % stays a %). A hand entry and a filing read that disagree are both kept and go to review; on the same day the filing's figure is in force.
- **Updated Manually** (v27, `hand.py`, kind "update"): one figure read from a filing, changed by the user with a source and a reason. The filing's reading is never changed; the update is applied again after every rebuild and after a single filing is read (`hand.apply_updates`, from the reading, so it can run twice). Figures worked out from it are worked out again and stay Calculated; totals a notice states are never changed by it. No new table.
- **Old ASX forms and Appendix 3G** (v28, `parsers.parse_3d/3e/3f/3g`): 3E has no purchase date, so it is the trading day before the notice, marked Calculated (user's choice); 3D's two columns run together, so a change is taken only when both columns are dated or numbered, else CHANGE_UNCLEAR; 3G issues go in table `issues`, never netted against purchases.
- **Existing data is not touched.** A version change adds columns only, and the first start of a new version saves a copy of the database in `backups\`. Report any change to existing rows.
- **Test with:** `python -P tests\test_parsers.py`, `python -P tests\test_fetch.py`, `python -P tests\test_forms.py`, `python -P tests\test_app.py`, `python -P tests\test_v22.py`, `python -P tests\test_v23.py`, `python -P tests\test_v24.py`, `python -P tests\test_v25.py`, `python -P tests\test_v26.py`, `python -P tests\test_v27.py` and `python -P tests\test_v28.py`. Use a scratch copy of the project for app testing, so `buyback.db` and `inbox\` hold only the user's own data.
